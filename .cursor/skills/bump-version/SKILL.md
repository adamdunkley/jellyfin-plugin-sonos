# Bump version for release

Set the same new version in these places only:

1. **`Directory.Build.props`** — `<Version>`, `<AssemblyVersion>`, `<FileVersion>`
2. **`build.yaml`** — `version:` and `changelog:` (short plain-English notes for implementors)
3. **`scripts/package.sh`** — the hardcoded `changelog` string written into zip `meta.json`

## Do not touch

- **`manifest.json`** — regenerated by `.github/workflows/publish.yaml` (`jellyfin-plugin-repo-action`) when a GitHub Release is published. Hand edits are overwritten.

## Verify

```bash
bash scripts/package.sh
```

Expect `artifacts/sonos_<version>_10.11.zip` and `artifacts/sonos_<version>_12.0.zip` (plus `.md5`). Confirm each zip’s `meta.json` has the new `version` and changelog.

## Commit

Prefer a dedicated bump commit, e.g. `Bump plugin version to X.Y.Z.W.`

`package.sh` / `sideload.sh` read the version from `Directory.Build.props`; no other hardcoded version strings need updating.
